# website

The phosphor-works site at <https://phosphor-works.org>: the app pages, the library pages, the guides, the news, the
palette and brand pages, and the Doxygen API reference under `/api/`. It is a static Astro site (`package.json` name
`phosphor-web`) that reads much of its content from the other phosphor-works repositories at build time.

The rules every phosphor-works repository follows come from the workspace repository, imported below. This file adds
website's own. The shared Claude Code tooling (the command guard, `phosphor-works:code-audit`, the shared reviewers,
the lesson index) comes from the `phosphor-works` plugin, which `.claude/settings.json` enables and
`workspace/tools/setup` installs.

@../workspace/claude/conventions.md

## Layout

- `src/pages/` has one route file for each URL. `src/layouts/BaseLayout.astro` wraps every page, and
  `src/components/` holds the shared parts (topbar, sidebar, cards, tabs, search).
- `src/data/` is the site data. `apps.ts` has one row for each suite app and feeds the Apps menu, the home grid, the
  footer and each app page. Keep its `status` honest, as its header says. `libraries.ts`, `nav.ts` and `palette.ts`
  feed the library pages, the navigation and the palette page.
- `src/content/news/` is the news collection, with its schema in `src/content.config.ts`.
- `src/data/plasmazones/` is generated by `npm run sync:plasmazones`. Change the source in PlasmaZones, not here.
  `settings.json` is the exception: its dump needs a PlasmaZones build, so it is synced and committed by hand.
- `scripts/` holds the build tooling (`build-docs.sh`, `fetch-branding.mjs`, `sync-plasmazones-data.mjs`,
  `upstream-checkouts.mjs`). `docs/` holds the Doxygen setup.
- `astro.config.mjs` sets `site`, `output: "static"` and the integrations (Expressive Code, astro-icon, sitemap,
  Pagefind, astro-compress). `ec.config.mjs` holds the Expressive Code options.

## Page text

Page text is user-facing text, so the writing rules of the conventions apply to it: page copy, titles, descriptions,
news entries and data strings that a page shows. Code comments are exempt.

## Build and run

| Command | Does |
| --- | --- |
| `npm run dev` | fetches branding, then starts `astro dev` on <http://localhost:4321> |
| `npm run build` | fetches branding, then builds the site into `dist/` |
| `npm run preview` | serves the built `dist/` |
| `npm run check` | `astro check`: types and content collections |
| `npm run docs` / `npm run docs:clean` | builds the Doxygen reference into `api/html/` (needs `doxygen` and `graphviz`) |
| `npm run sync:plasmazones` | regenerates `src/data/plasmazones/` and scaffolds a news entry for a new x.y.0 release |
| `npm run fetch:branding` | downloads the pinned branding release into `vendor/branding/` |

The Pagefind index is made by the build, so search works under `npm run preview` and not under `npm run dev`.

## Other repositories

- branding: `scripts/fetch-branding.mjs` is the only place of the pin (version, URL, file and SHA-256, changed
  together). The release unpacks into `vendor/branding/`, which is gitignored. `public/brand/assets` and
  `public/palette/phosphor.toml` are symlinks into it, and `src/data/palette.ts` and the Expressive Code theme
  (`src/themes/`) read the palette TOML.
- The sibling checkouts `../PlasmaZones`, `../phosphor-surface-packs`, `../phosphor-libs`, `../phosphor-engine-libs`,
  `../phosphor-shell-libs` and `../Afterglow` feed the galleries, the API reference and the Afterglow pages. `scripts/upstream-checkouts.mjs`
  finds them. `PHOSPHOR_WORKS_SRC` moves all of them, and a per-repository variable (`PLASMAZONES_SRC`,
  `AFTERGLOW_SRC` and others, listed in the README) moves one.
- Afterglow: `src/lib/remark-afterglow-docs.mjs` renders Afterglow's `docs/` as `/afterglow/<doc>/`. It lifts the H1
  into the page title and points relative links at site pages or GitHub.
- phosphor-bots: the issues pages (`src/pages/issues/`) are served on issues.phosphor-works.org, beside the files
  that Glim writes there. The browser reads Glim's `/api/posts.json`. The sitemap leaves them out.
- Algorithm previews need the `luau` CLI on `PATH` (or `LUAU`). Without it the sync keeps `algorithms.json`.

## CI and deploy

`.github/workflows/check.yml` runs on every pull request: `npm run check`, the Astro build and lychee over the
site's own pages, which fails on a broken internal link (it skips `/api/`, which only the deploy builds).

`.github/workflows/deploy.yml` runs on a push to `main`, every night at 09:17 UTC and on demand.

The build job clones each upstream at the tip of `main` into `_src/`, builds `luau` from the Luau pin of
phosphor-libs, fetches branding, runs the PlasmaZones sync, builds the Doxygen reference and runs `npx astro build`.
It merges `api/html/` into `dist/api/html/`, then runs lychee over `dist/`. lychee is advisory (`fail: false`).
The deploy job uploads one tarball over SFTP through a Cloudflare Tunnel to the project server, which switches the
live site to it. The secrets are in the `vps` environment. Nothing the build syncs is committed back.
